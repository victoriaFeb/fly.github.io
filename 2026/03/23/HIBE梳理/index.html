一、BKP-HIBE

Gen(par)

👉 执行者：Root PKG

输出：

  • pk → 所有人
  • dk → 系统内部（给后续生成用）
  • sk → Root PKG 自己（MAC key 等）

USKGen(sk, id)

👉 执行者：Root PKG

👉 作用：

给某个 identity 生成“第一份私钥”

usk[id] → 给用户
udk[id] → 给用户（用于继续 delegation）

用户一拿到 (usk, udk)，就“升级为一个 PKG”

USKDel(dk, usk[id], udk[id], id → id′)

👉 执行者：当前节点（父 identity）

输入：

  • 自己的：
    • usk[id]
    • udk[id]
  • 公共参数里的 dk
  • 子身份 id′

输出：

Enc(pk, id)

👉 执行者：发送者

输出：

👉 不需要任何 PKG

Dec(usk[id], id, C)

👉 执行者：接收者

二、迁移HIBE

BKP主干

pk = 对 MAC 秘钥的承诺

usk = MAC tag + 证明

ct = 对公开承诺pk按身份做随机线性组合

依赖 pairing、GS proof、隐式群表示

BKP 的核心主干不是“把秘密群编码起来”这件事本身，而是“把 MAC 验证关系嵌进 IBE 的公钥 / 用户密钥 / 密文之间的线性一致性里”。

GS proof：

FG-IBE替换

NC1 里的矩阵承诺 + subset-membership 切换 + 一个 GS-like 证明思路

利用D0矩阵的具体结构实现hiding

不能让 delegation material 泄露出足以直接恢复或约束 MAC secret (X,x0)(X,x_0)(X,x0) 的信息，也不能破坏他们依赖的 commitments-hiding / switching 证明骨架。

关键继承

BKP: 群承诺 + pairing 验证 + dual-system 式切换

FG: 矩阵承诺 + 线性代数验证 + matrix-switching / subset-membership 切换

设计dk核心思想

dk 不能直接给出一个让子节点能恢复或强约束 MAC secret 结构的对象；它必须只是支持 delegation 所需的“派生信息”，同时仍然允许维持：

  1. pk 对 secret 的承诺/隐藏；
  2. user key 可以被模拟；
  3. challenge ciphertext 仍能被切换成 invalid / random；
  4. 从攻击者视角能把对 HIBE 的攻击还原成对 MAC / subset-membership 的攻击。

FG 实现HIBE难点

subset-membership,

switching A:D0→D1→D0

改变 r 的首位分布，

不显式求逆/不使用 pairings 的 extractability

这些技术还没有自然延伸成一个“delegatable affine MAC + fine-grained proof system”的完整层级机制

关键问题

  • delegation 需要哪类线性操作？

  • 这些操作能否只靠“派生态”完成？能否给某些吸收了secret的派生矩阵而非直接给B或X？

  • 安全证明是否还能走

    USK simulation 不用知道全部 MAC secret；

    challenge 仍可通过两次矩阵分布切换变成可还原到 MAC 的形式；

    不需要矩阵求逆。

    • 让仿射 MAC 适配 HIBE 的 “身份分层 + 密钥委托” 特性，是构建可委托 HIBE 的核心 MAC 安全属性。

三、安全性

1.选择明文安全性 (CPA Security)

1.1 定义

选择明文安全性（Chosen-Plaintext Attack, CPA） 是对称加密与公钥加密中最基础、最常用的安全概念，描述攻击者在可以任意选择明文并获得对应密文的情况下，仍然无法攻破加密方案。

1.2 攻击模型

攻击者拥有：

  • 加密算法公开
  • 可以自由选择任意明文 m，获取其加密后的密文 c
  • 目标：区分两个明文对应的密文，或恢复密钥 / 明文

1.3 安全游戏（CPA Game）

  1. 挑战者生成密钥 (pk,sk)

  2. 攻击者可以多次询问加密预言机：提交 m，得到 c=Enc(pk,m)

  3. 攻击者提交两个等长明文 m0,m1

  4. 挑战者随机选 b∈{0,1}，返回 c∗=Enc(pk,mb)

  5. 攻击者猜测 b

    若攻击者的优势可忽略，则加密方案是CPA 安全的。

1.4 核心意义

  • 公钥加密必须满足 CPA 安全（因为公钥公开，攻击者天然可以任意加密）
  • 意味着加密必须是概率性的（同一明文多次加密得到不同密文）
  • 确定性加密（如 ECB 模式）不是 CPA 安全

2.选择身份攻击 (ID-CPA / Selective-ID Attack)

这个概念主要出现在基于身份的加密（IBE）、属性基加密（ABE）等密码体制中。

2.1 选择身份攻击（Selective-ID Attack, sID-CPA）

攻击者在系统建立之前，就预先选定一个目标身份 ID∗，之后再获得系统参数，并尝试攻破该身份的加密安全性。

2.2 攻击游戏

  1. 攻击者先宣布要攻击的目标身份 ID∗
  2. 挑战者生成系统参数 PP，主密钥 msk
  3. 攻击者可以询问任意非目标身份的私钥
  4. 攻击者提交 m0,m1 与 ID∗，挑战者返回挑战密文
  5. 攻击者猜测比特 b

若优势可忽略，则方案是选择身份安全（sID-CPA）。

2.3 自适应身份攻击（Adaptive-ID, ID-CPA）

更强的安全模型：

  • 攻击者不预先选 ID

  • 可以自适应地、任意询问任何身份的私钥

  • 最后才选择攻击哪个 ID∗
